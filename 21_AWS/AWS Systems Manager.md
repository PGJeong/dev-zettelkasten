- **AWS Systems Manager(SSM**)는 AWS, 온프레미스, 타사 클라우드 등 **하이브리드 환경의 인프라와 애플리케이션을 중앙에서 통합 관리**하는 서비스

- 환경(개발/프로덕션), 프로젝트 등 특정 기준에 따라 리소스를 그룹화하여 관리 가능
- Systems Manager는 AWS Config, EventBridge, AWS CloudTrail 등의 서비스에서 데이터를 수집하며, 통합된 액세스 제어를 위해 AWS IAM을 사용

- **핵심 역할:** 대규모 리소스 관리 간소화, 운영 문제 빠른 감지/해결, 보안 및 규정 준수 유지
- **지원 대상:** EC2, RDS, ECS, EKS 등 다양한 AWS 리소스 및 온프레미스 서버/가상 머신(VM)

![[../80_Assets/Pasted image 20260804201601.png]]

- **운영 관리** - AWS 리소스의 운영 데이터를 중앙에서 관리
- **애플리케이션 관리** - 실행 중인 애플리케이션 모니터링 및 관리
- **변경 관리** - 안전하고 감사 가능한 방식으로 리소스 변경 수행
- **노드 관리** - EC2, 온프레미스 서버 등 다양한 노드를 대규모로 원격 관리

### 주요 개념

| **주요 용어**                                    | **핵심 내용**                                                     |
| -------------------------------------------- | ------------------------------------------------------------- |
| **관리형 노드 (Managed Node)**                    | SSM을 사용하도록 구성된 모든 시스템(EC2, 온프레미스 서버 등)                        |
| **SSM Agent<br>(AWS Systems Manager Agent)** | 관리형 노드에 설치되어 Systems Manager가 원격 제어 및 업데이트를 수행할 수 있게 돕는 소프트웨어 |
| **Systems Manager 문서**                       | 인스턴스/AWS 리소스에서 실행할 작업이나 스크립트가 정의된 사전 구성 문서 (450개 이상 제공)       |
| **패치 기준 (Patch Baseline)**                   | OS, 제품, 심각도별로 자동 승인할 패치 규칙 및 허용/거부 패치 목록을 정의한 기준              |
| **State Manager 연결**                         | 서버의 특정 상태(예: 바이러스 백신 실행, 특정 포트 차단)를 정의하고 지속해서 유지·적용하는 프로세스    |
| **Parameter Store**                          | 비밀번호, DB 접속 문자열, AMI ID 등을 일반 텍스트 또는 암호화 데이터로 중앙 저장·참조하는 기능   |
| **OpsCenter OpsItems**                       | 운영 문제를 조사하고 수정할 수 있도록 리소스 세부 정보, 경보 기록, 타임라인을 제공하는 단위         |

# 아키텍처 및 사용 사례

### 노드 관리

- EC2, ECS/EKS 클러스터, 온프레미스 서버, 타사 클라우드 VM 등 다양한 환경의 관리형 노드에 접근하고 중앙에서 설정할 수 있음

![[../80_Assets/Pasted image 20260804203202.png]]

- **Patch Manager** - 운영체제(OS) 및 애플리케이션의 보안 패치와 업데이트 적용을 자동화하는 기능 (미리 정의된 패치 기준에 따라)
- **State Manager** - 관리형 노드를 사용자가 정의한 특정 상태(State)로 항상 유지하도록 만드는 기능 (e.g. 특정 보안 포트가 닫혀 있어야 함)
- **자동화** - 복잡하고 반복적인 AWS 리소스 관리 프로세스를 자동화 런북(Runbook) 스크립트로 실행하는 기능 (e.g. 단일 서버 작업을 넘어 RDS 스냅샷 생성 등 복수 리소스 연계 작업 처리)
- **Session Manager** - 브라우저나 AWS CLI를 통해 인스턴스에 안전하게 대화형 터미널(쉘)로 접속할 수 있게 해주는 기능
- **Run Command** - SSH/RDP 접속 없이 여러 서버에 일회성 스크립트나 명령어를 원격으로 즉시 실행하는 기능

### 작업 및 구성 관리

- EventBridge 이벤트나 CloudWatch 알림을 기반으로 OpsCenter에 운영 이슈(OpsItems)를 자동 생성하고, 런북 실행이나 인시던트 관리(Incident Manager)로 신속히 해결

![[../80_Assets/Pasted image 20260804204403.png]]

- **Change Manager** - 애플리케이션 구성 및 인프라에 대한 변경을 요청·승인·실행·보고하는 기업용 변경 관리 프레임워크 (무단 변경 방지)
- **OpsCenter** - AWS 리소스와 관련된 운영 문제(OpsItems)를 한곳에서 집계, 조사 및 해결하는 중앙 대시보드
- **Incident Manager** - 서비스 중단이나 장애 발생 시 비상 대응 절차를 가동해 신속한 복구를 돕는 도구

### 운영 및 보안 고려사항

- **최소 권한의 원칙** - IAM을 활용해 사용자 및 리소스에 대한 Systems Manager 접근 권한을 최소한으로 제한
- **추적 및 모니터링** - CloudWatch, AWS Config, CloudTrail과의 기본 통합을 통해 작업 및 사용 이력을 투명하게 추적
