- **Amazon Elastic Compute Cloud(EC2)**는 많은 AWS 제품의 기초
- **인스턴스**는 기상 머신(VM)임
- **인스턴스 유형**은 CPU, 메모리와 같이 인스턴스를 만드는 가상 하드웨어 구성 요소의 조합
- 인스턴스 유형은 **인스턴스 패밀리**로 그룹화됨 (각 인스턴스 패밀리는 특정 사용 유형에 최적화)
- 인스턴스 패밀리는 사용되는 프로세서와 스토리지 조합에 따른 그룹인 **하위 패밀리**를 가짐
- 가상 중앙 처리 장치(**vCPU**)는 처리 능력의 척도
	- 대부분의 인스턴스 유형에서 vCPU는 기본 물리적 CPU 코어의 한 스레드를 나타냄
	- 예를 들어 2개의 CPU 코어를 가지고 있고 한 코어당 2개의 스레드가 있다면 vCPU는 4개

![[../80_Assets/Pasted image 20260707223457.png]]
- **인스턴스 크기** - 크기가 클수록 리소스가 많음 (vCPU, 메모리, 스토리지, 네트워킹의 총 용량)

![[../80_Assets/Pasted image 20260707223528.png]]

- AWS 인스턴스는 현재 5개의 패밀리로 분류됨

1. **범용**
	- 컴퓨팅, 메모리 및 네트워킹 리소스를 균형 있게 제공하며 다양한 워크로드에 사용 가능
	- **버스트 가능 인스턴스 옵션** - 버스트 가능 인스턴스(T 패밀리 등)는 평소에는 낮은 기준(Baseline) 성능을 유지하다가, 작업량이 급증할 때 성능을 최대치로 끌어올리는 CPU 옵션

2. **메모리 최적화**
	- 메모리에서 대규모 데이터 세트를 처리하는 워크로드에 적합

3. **스토리지 최적화**
	- 로컬 스토리지의 큰 데이터 세트에 순차적 읽기 및 쓰기 액세스가 많이 필요한 워크로드에 적합 (지연 시간이 짧은 수만 단위의 무작위 초당 입출력(I/O) 작업 수(IOPS)를 제공)

4. **컴퓨팅 최적화**
	- 고성능 프로세서를 활용하는 컴퓨팅 집약적인 애플리케이션에 적합
	- 배치 처리, 과학 모델링, 게임 서버, 기계 학습(ML) 추론 등

5. **가속 컴퓨팅**
	- 하드웨어 액셀러레이터 또는 코프로세서를 사용하여 일부 기능을 CPU에서 실행되는 소프트웨어에서 보다 더 효율적으로 수행
	- 컴퓨팅 집약적 워크로드에서 병렬화를 촉진해 처리량(throughput)을 높임
	- 부동 소수점 수 계산, 그래픽 처리, 데이터 패턴 일치 등

# 인스턴스 유형 변경

- 요구 사항이 변함에 따라, **인스턴스 유형을 변경**할 수 있음
- 일부 인스턴스 유형은 인스턴스 실행 중에 변경할 수 있음 (다른 인스턴스 변경, 특히 다른 프로세서 유형으로 전환하는 경우에는 인스턴스를 중지해야함)
- **신형 인스턴스 유형을 선택**하면 대개 **비용이 절감되고 성능이 개선**되는데, 이는 신형 인스턴스가 더 빠르고 최적화되고 쉽게 이용 가능한 하드웨어에서 실행되기 때문

### AWS Compute Optimizer

- 머신러닝을 기반으로 리소스 사용 이력을 분석하여, 비용을 절감하고 성능을 높일 수 있는 **최적의 인스턴스 크기와 사양을 자동으로 추천**해 주는 서비스 (**비용과 성능의 균형**)
- 최근 14일간의 CloudWatch 지표(CPU, 메모리, 네트워크, 스토리지 I/O 등)를 분석하여, 리소스가 낭비되는 '오버프로비저닝(Over-provisioning)' 상태나 성능 저하 위험이 있는 '언더프로비저닝(Under-provisioning)' 상태를 진단 

### 요금 계산기

- AWS 사용 예산을 계산하는 데 사용할 수 있는 웹 기반 도구
- 솔루션을 구축하기 전에 모델링하고, AWS 서비스 요금 수준을 탐색하며, 견적 계산을 검토하는 데 사용

### Cost Explorer

- 비용 및 사용량을 확인하고 분석
- 최대 12개월까지 과거 데이터를 확인하고, 향후 12개월의 지출 금액을 예측하며, 구매할 예약 인스턴스를 추천받을 수 있움

# 인스턴스 요금

### 클라우드 컴퓨팅의 장검

1. **규모의 경제** - 수많은 고객의 사용량이 클라우드에 집계되므로 AWS와 같은 공급자는 높은 규모의 경제를 달성할 수 있으며, 따라서 사용량에 따라 지불하는 종량제 요금이 더 낮아짐
2. **용량 추정 불필요** - 사용하는 용량을 아주 적거나 아주 많게 자유자재로 조정할 수 있으며, 필요에 따라 자동으로 확장 및 축소하도록 환경을 구성할 수도 있음
3. **속도 및 민첩성 향상** - 클라우드 컴퓨팅 환경에서는 새 IT 리소스를 클릭 몇 번으로 사용할 수 있어, 실험 및 개발에 드는 비용과 시간이 절감되고 조직의 민첩성이 향상됨
4. **데이터 센터 운영 및 유지 관리 불필요** - 인프라가 아니라 비즈니스를 차별화하는 프로젝트에 집중할 수 있음
5. **몇 분 만에 전 세계에 배포** - 클릭 몇 번으로 세계 곳곳의 여러 AWS 리전에 애플리케이션을 손쉽게 배포할 수 있음

### Amazon EC2 요금제

- **온디맨드** - **시간당 또는 초당 컴퓨팅 용량**에 대한 비용을 지불 (종량제)
	- 선결제 금액이나 장기 약정 없이 유연하게 사용
	- 변동이 심하거나 예측할 수 없는 단기 워크로드가 있으며, 중단되어서는 안 되는 애플리케이션

- **스팟** - **여유 EC2 호스트 용량을 사용**하여 온디맨드 대비 최대 90%의 비용을 절감
	- 시작 및 종료 시간이 유연하고 중단이 허용되는 애플리케이션
	- 컴퓨팅 요금이 요금 범위 안에 있을 때만 실행되기 원하는 애플리케이션

- **Savings Plans** - 1년 또는 3년의 **특정 기간 동안 시간당 금액 약정**을 통해 비용을 절감
	- 1년 또는 3년의 기간 동안 시간당 USD 단위의 **필수 사용량**이 있음
	- 유연하게 사용량을 확장할 수 있어서 지속적으로 비용을 절감할 수 있음 (약정한 금액까지는 할인된 요금이 적용되고, 초과 분에 대해서만 온디맨드 요금이 부과)
	- RI와 달리 인스턴스 크기, OS, 리전, 인스턴스 패밀리를 변경해도 할인이 자동 적용
	- **Compute Savings Plans** - EC2뿐만 아니라 AWS Fargate, AWS Lambda 지출까지 통합하여 할인하므로 유연성이 가장 높음
	- **EC2 Instance Savings Plans** - 특정 인스턴스 패밀리와 리전(예: 버지니아 북부의 m5)을 지정해야 하지만 할인율이 더 높음

- **예약 인스턴스(RI)** - **특정 인스턴스 유형과 리전(또는 AZ)을 미리 예약**하는 방식
	- 특정 인스턴스 사양을 지정하여 구매하며, 해당 조건을 충족할 때 할인 적용
	- 실제 사용량과 관계없이 예약 인스턴스 기간 전체에 대해 요금을 지불
	- **용량 예약**을 통해 특정 가용 영역(AZ)을 지정하면 인스턴스 실행 여부와 관계없이 해당 자리를 보장받을 수 있음
	- **표준(Standard) RI** - 인스턴스 패밀리를 변경할 수 없으며, 할인율이 가장 높음
	- **전환형(Convertible) RI** - OS, 인스턴스 패밀리 등을 도중에 변경할 수 있으나 할인율이 약간 낮음

| 비교 항목          | 예약 인스턴스 (RI)               | Savings Plans                     |
| -------------- | -------------------------- | --------------------------------- |
| **약정 대상**      | 인스턴스 형태 및 수량               | 시간당 지출 비용 ($)                     |
| **인프라 변경 유연성** | 낮음 (전환형 RI만 일부 가능)         | 매우 높음 (자동 적용)                     |
| **용량 예약 기능**   | 가능 (특정 가용 영역 지정 시)         | 불가능 (별도 용량 예약 필요)                 |
| **관리 편의성**     | 인스턴스 변경 시 수동 재배치 필요        | AWS가 최적의 할인을 자동 계산                |

- **전용 호스트** - 전용의 물리적 EC2 서버
	- 온디맨드 또는 예약 인스턴스로 구매 가능
	- 서버 기반 소프트웨어 라이선스가 필요한 워크로드에 적합
	- 보안 및 규정에 의해 다른 테넌트와 하드웨어를 공유할 수 없는 워크로드에 적합
